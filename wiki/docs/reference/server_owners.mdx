# For server owners

## Where things live

- **Config**: per world, in `<world>/serverconfig/mobstacker.json`. Written whenever a setting changes;
  after editing it by hand, run `/mobstacker reload`. Upgrading from a version before 1.4? Copy the old
  `config/mobstacker.json` there.
- **Stacks**: inside the mobs themselves, saved with the world like any other mob data.
- **Players' own choices** (which region boxes they show, the box style, X-ray on or off): on each
  player's computer, in `config/mobstacker-overlay.json`. Never sent to the server.

## Players without the mod

Stacking is done on the server, so players do not need the mod to play on a server that has it. They
see stacks as ordinary mobs with a `Cow x16` name. Without the mod they have no config screen, no
region boxes, and `Dinnerbone`/`Grumm` stacks are not drawn upside down for them. The mod's network
channels are optional, so a player without it is never sent anything or kicked.

## Permissions

| Who | May |
|---|---|
| Operators (level 2) | everything under `/mobstacker`, and edit the config from the config screen |
| A region's owner | `/mobstacker region share` on their own regions |
| Everybody with the mod | open the config screen read-only, and see the regions they may see |

See [Private regions]($regions/private_regions) for the `mobstacker.regions.viewall` permission.

## Command answers

Many servers set the gamerule `sendCommandFeedback` to false because command blocks spam the chat.
That also hides every answer `/mobstacker` gives. Turn this on:

```
/mobstacker set alwaysShowFeedback true
```

and the player who **typed** a `/mobstacker` command gets its answer again. Command blocks and
functions stay quiet, also when they run the command as a player (`execute as`). Vanilla commands are
not affected. Errors are always shown either way.

## Java arguments

| Argument | Where | Effect |
|---|---|---|
| `-Dmobstacker.xray=true` | the server (in singleplayer, your game) | allows region boxes through walls, see [Seeing regions]($regions/seeing_regions#through-walls-x-ray) |
| `-Dmobstacker.overlayDebug=true` | a player's game | logs what the region boxes found, for bug reports about boxes |
| `-Dmobstacker.selftest=true` | the server | adds `/mobstacker selftest`, which checks every setting against a sandbox config. For development. |

## Spawning and despawning

All of these are in `/mobstacker help mobcaps` and on the config screen's **Spawning & despawning**
page.

### Spawn caps

Vanilla stops spawning a kind of mob once enough of them are around: 70 monsters, 10 animals and so
on. **Every mob in a stack counts towards that limit** (`countStackMembers`, on), so a world with
stacks has as many mobs as vanilla, only in fewer entities: the server does less work and the game
plays the same.

- `countStackMembers false` counts a whole stack as one mob. Far more mobs can then exist at once,
  and farms that rely on spawning give more.
- Each cap is a setting of its own, from 0 to 128, global only. The defaults are vanilla's:

```
/mobstacker set monsterMobCap 70
/mobstacker set creatureMobCap 10
/mobstacker set ambientMobCap 15
/mobstacker set axolotlsMobCap 5
/mobstacker set undergroundWaterCreatureMobCap 5
/mobstacker set waterCreatureMobCap 5
/mobstacker set waterAmbientMobCap 20
```

> [!NOTE]
> Before 1.12.0 the mod lowered the caps to 22/5/7/2/2/2/8 even with stacking off, and counted a stack
> as one mob. A config that still holds exactly those numbers is moved to vanilla's the first time
> 1.12.0 loads it (the server log says so). Caps somebody changed stay as they are.

### Despawning

- **`despawnPickedUpMobs`** (off): in vanilla a mob that picks up an item, a zombie taking a sword off
  the ground for instance, never despawns again, and such mobs pile up. With this on it despawns like
  any other mob and **drops what it picked up** when it goes; an enderman carrying a block drops the
  block. Gear a mob was born with despawns with it, as in vanilla. A mob that was persistent anyway
  (named, from a structure) stays. Can be set per region, which is how you exempt a place.
- **`persistentStackSize`** (0, off): a stack of at least this many mobs never despawns on its own, for
  pens and farms that keep their mobs. With 0 a stack despawns like a single mob: all at once, which is
  how often vanilla would have despawned the crowd it stands for. Per region too.

This is the part of [Let Me Despawn](https://modrinth.com/mod/lmd) that matters with stacks. Use one or
the other: both handle the same mobs, and two mods deciding when one despawns is one too many.

## Removing the mod

> [!CAUTION]
> Without the mod a stack is **one mob**, and every other mob it stood for is gone. Unstack first.

```
/mobstacker set stackMode off        # or they merge again straight away
/mobstacker unstack loaded confirm   # every stack in the loaded chunks
```

- Mobs come back a hundred per tick, set down apart where there is room, never on the far side of a
  wall or fence, so they do not hurt each other by crowding. A stack with no room around it is left
  partly stacked and reported.
- Only **loaded** chunks can be reached: visit (or `/forceload`) the farms that matter first.
- `unstack <radius>` does the same around you, and also asks for `confirm` once it would bring back
  more than 500 mobs.

Stacks without AI think again on their own once the mod is gone: the mod never writes `NoAI` into a
mob.
